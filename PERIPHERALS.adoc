The two board sections are self-contained and describe the *normal firmware*.
Assignments come from `boards/i6x/hardware.hpp`, `boards/i6s/hardware.hpp` and
the shared drivers in `platform/stm32f072/`.
Standalone diagnostic/measurement images are not the normal application.

WARNING: MCU pin names are not connector pin numbers or a guarantee of accessible
pads. Check the actual PCB revision and circuit before soldering.
Use compatible 3.3 V logic and a common ground; do not apply module supply voltage
to signal pins or power an RF module directly from an MCU GPIO.
Disconnect battery/USB before hardware modifications and disconnect motors/remove
propellers for all tests. Neutral output is not a guaranteed motor-off failsafe.

[[i6x]]
== Flysky FS-i6X

=== Processor, clocks and execution

* STM32F072xB, Cortex-M0, 128 KiB internal flash, 16 KiB SRAM.
  Settings are not stored in internal flash.
* Startup uses HSI, then the 8 MHz HSE and PLL x6 provide 48 MHz
  CPU/AHB/APB clocks. Flash uses one wait state and prefetch.
* A cooperative main loop runs ADC processing, keys, UI, EEPROM and CRSF.
  No RTOS or SysTick scheduling; drivers have bounded service steps.
* TIM2 is a free-running 32-bit 1 MHz timebase. Its CC1 schedules AFHDS 2A
  deadlines without an output pin.
* IWDG uses LSI/64: nominally 2 s during startup and about 500.8 ms at runtime,
  refreshed by the main loop every 50 ms.
  DBGMCU pauses TIM2/IWDG while the debugger halts the CPU.
* RTC backup registers retain reset/fault diagnostics: BKP0 magic,
  BKP1 reset counter, BKP2 fault and BKP3 fault magic.
  The RTC is not a calendar clock.

=== ADC1: stock controls and expansion

ADC1 runs at 12 MHz with 12-bit conversion and 239.5 sample cycles plus 12.5
conversion cycles per channel. DMA1 channel 1 transfers 16-bit samples in a
high-priority circular buffer. The application publishes controls every 5 ms
and treats ADC data missing for 10 ms as an error.

[cols="1,1,3",options="header"]
|===
|GPIO |ADC channel |Stock input
|PA0 |0 |Right stick horizontal (RH).
|PA1 |1 |Right stick vertical (RV).
|PA2 |2 |Left stick vertical (LV).
|PA3 |3 |Left stick horizontal (LH).
|PA4 |4 |SA, two-position switch.
|PA5 |5 |SB, two-position switch.
|PA6 |6 |VRA.
|PA7 |7 |VRB.
|PB0 |8 |SC, three-position switch.
|PB1 |9 |SD, two-position switch.
|PC0 |10 |Battery-voltage measurement.
|===

Stick mode determines the logical stick assignment. SA through SD are measured
as analog voltages, not GPIO switches.

[cols="1,1,2",options="header"]
|===
|GPIO |ADC channel |Additional source
|PC2 |12 |VRC.
|PC3 |13 |VRD.
|PC4 |14 |VRE.
|PC5 |15 |VRF.
|===

There are 11 stock ADC channels, 15 when all four extra analog channels are used.
Each extra input can be configured individually as
*Off / Pot / Pot-D / 2pos / 3pos / 6pos* and calibrated.
Off inputs disappear from source selection lists.
This requires `CORETX_EXTENDED_INPUTS=ON`.
`CORETX_ADC_COHERENT_SNAPSHOTS=ON` optionally uses two DMA halves for coherent
snapshots; it consumes additional RAM and is off by default.

=== Additional digital switches and SWD

[cols="1,1,3",options="header"]
|===
|GPIO |Source |Configuration
|PC12 |SE |Off, two-position, or three-position using PC12 and PC15.
|PC15 |SF |Off or two-position; consumed/hidden when SE is three-position.
|PA13/PA14 |SWDIO/SWCLK |Remain debug pins; not used for these extra switches.
|===

Expansion switch inputs are active low with pull-ups; contacts connect to GND.
Each can be Off independently. With SE configured as three-position:
neither contact active means middle, SE active means up, SF active means down.
Both contacts active is an invalid combination after the 20 ms debounce time
and is reported as a control error.
Only SE remains selectable for the combined switch.
These GPIO inputs do not share the CRSF UART pins.

=== Key matrix and trims

[cols="2,3",options="header"]
|===
|Pins |Use
|PC6/PC7/PC8 |Three open-drain matrix columns.
|PD12/PD13/PD14/PD15 |Four matrix rows with pull-ups.
|===

One column is scanned each millisecond. The matrix provides Up, Down, OK,
Cancel and four trim rockers. Ghost rectangles are suppressed.
Trim mapping follows stick mode; trim controls can alternatively act as
RC switch sources T1 through T4. No key interrupt is used.

=== Internal A7105 / AFHDS 2A

[cols="2,3",options="header"]
|===
|Pins/peripheral |Use
|SPI1 PE13/PE14/PE15, AF1 |SCK/MISO/MOSI, mode 0, 8 bit, 6 MHz.
|PE12 |A7105 chip select, active low.
|PE8/PE9 |RX_EN/TX_EN, active low; both high switches the front end off.
|PE10/PE11 |Antenna selection.
|PB2 |GIO2, falling-edge EXTI2.
|TIM2 CC1 |RF scheduling/deadline interrupt.
|===

`CORETX_A7105=ON` enables this RF path. Only AFHDS 2A is implemented for the
internal A7105; internal and external RF are not active simultaneously.

=== External CRSF module

[cols="2,3",options="header"]
|===
|Pins/peripheral |Use
|USART2 TX: PD5 AF0 |Transmitter to module.
|USART2 RX: PA15 AF1 |Module to transmitter.
|PC13 |Module-power enable, active low.
|DMA1 channel 7 |UART TX, normal DMA.
|DMA1 channel 6 |UART RX, circular DMA, 256-byte buffer.
|SYSCFG |USART2 DMA remap to channels 6/7.
|===

UART uses 8N1, normally 400000 baud. Selectable rates are 115200, 400000,
416666, 420000, 921600, 1870000, 3750000 and 5250000 baud.
DMA completion and RX progress are polled; no USART/DMA ISR is used.
Use compatible logic levels, common ground and a suitable module supply;
PC13 is a control signal, not a module supply rating.

`CORETX_CRSF=ON` enables channels, telemetry and module configuration.
*Radio setup -> External module* additionally permits/disables the external RF
path at runtime. Disable external RF before changing this setting.
`CORETX_MULTISWITCH=ON` adds dashboards and SET4 commands when CRSF is compiled in.

=== LCD and buzzer

[cols="2,3",options="header"]
|===
|Pins/peripheral |Use
|PE0 through PE7 |128x64 LCD, 8-bit parallel data bus.
|PB3/PB4/PB5 |LCD RS/RESET/RW.
|PD2/PD7 |LCD CS/E.
|PF3/PC9 |Backlight/brightness GPIO, currently fixed on; no PWM timer.
|PA8 AF2, TIM1 CH1 |Active-low buzzer PWM.
|===

LCD updates are cooperative, with a 100 us service budget.
The buzzer generates 10 ms tones: 2200 Hz for controls/trims/detents and
1100 Hz for MultiSwitch feedback, without a timer ISR.

=== External EEPROM

I2C2 uses *PB10 SCL / PB11 SDA, AF1, open drain*.
The 16 KiB EEPROM has 64-byte pages. `CORETX_I2C_FAST_MODE=ON` selects
approximately 400 kHz; OFF selects 100 kHz.
The cooperative driver handles writes and completion polling without an I2C ISR.

Calibration, radio setup, eight model slots and input setup use binary,
CRC-protected records with two-bank/journal recovery.
Model records are 768 bytes per bank.
Input setup uses format 3 and can read older formats 1/2.
An internal-flash DFU backup does *not* contain this EEPROM.

=== Power, interrupts and unused resources

The i6X uses its mechanical power switch; there is no i6S-style PB15 soft latch
or two-button shutdown controller.
For the first flash from factory firmware, temporarily bridge the *R53 pads*
to select ROM DFU; no resistor removal is required in the documented procedure.
See link:BUILDING.adoc#first-flash-i6x[i6X first-flash steps and PCB reference].
After installing CoreTX with startup DFU support, hold both horizontal trims
*inward* during cold power-on for updates without a bridge.
The matrix combination is PC6/PD13 plus PC7/PD14 (bits 1 and 6), independent of
stick mode. RF stays off; ROM DFU is entered before the watchdog starts.
See link:BUILDING.adoc#dfu-update[power-on DFU and recovery].

In normal firmware, with A7105 support enabled, the only application ISRs are
`TIM2_IRQHandler` and `EXTI2_3_IRQHandler`, both at priority 0
(`boards/common/rf_interrupts.cpp`). Shared RF state uses guarded handoff.
ADC/DMA, UART, EEPROM, keys, LCD and buzzer are serviced by the main loop.

DMA1 channel 1 is ADC, channels 6/7 are CRSF RX/TX; channels 2 through 5 are unused.
I2C1 and USART1 are unused. USB, CAN, DAC, comparators, SPI2 and other timers
are not used by the running application.
USB ROM DFU is a bootloader function, not a CoreTX USB implementation.
Unused peripherals do not imply their pins are free or exposed.

`CORETX_A7105=OFF` removes SPI/RF interrupt use, but TIM2 remains the timebase.
`CORETX_CRSF=OFF` removes UART/CRSF DMA use; safe module-off GPIO handling remains.
Do not infer that a build option makes connected RF hardware safe to rewire while powered.

=== Additional digital switches, SWD and module-pin ownership

[cols="1,1,1,3",options="header"]
|===
|Connector |GPIO |Source |Configuration
|J4 |PA13 |SG |Off, two-position, or three-position using PA13 and PA14.
|J4 |PA14 |SH |Off or two-position; consumed/hidden when SG is three-position.
|J15 |PB6 |SN |Off, two-position, or three-position using PB6 and PB7; only without external module.
|J15 |PB7 |SO |Off or two-position; consumed/hidden when SN is three-position; only without external module.
|J15 |PF10 |SP |Off or two-position, independent of external module.
|===

All five additional GPIOs can be Off individually and then disappear from
source lists. Inputs are active low with pull-ups; switch contacts connect to GND.
For each paired three-position switch, neither contact means middle, the first
contact means up and the second down.
Both contacts active is invalid after 20 ms debounce and is reported as a
control error. Only the combined SG or SN remains selectable.

PA13/PA14 are normally SWDIO/SWCLK. Using either as a switch restricts debugging.
Releasing both restores AF0 debug mode, PA13 pull-up and PA14 pull-down.

*Radio setup -> External module = Yes* reserves PB6/PB7 for CRSF;
stored SN/SO settings are retained but inactive. With *No*, external RF is
disabled and these pins can be configured as switches.
Do not change this setting while external RF is running.
J4 switches and PF10 can coexist with CRSF.
PF10 is not a PPM output in CoreTX.

WARNING: Physically disconnect/isolate switches on PB6/PB7 before enabling the
external module. A software setting cannot remove a switch shorting a UART line.

=== Rear buttons, setup controls and LEDs

[cols="2,2,3",options="header"]
|===
|Pins |RC input |Setup function
|PA9, rear left |SE, active low |OK; hold for OK-long.
|PA10, rear right |SF, active low |Back; hold to leave the menu.
|PA6, VRA |Normal analog input |Vertical setup navigation.
|PA7, VRB |Normal analog input |Setup navigation, same up/down jog as VRA.
|PD10/PD11 |None |LEDs below the power buttons, active high.
|===

Rear buttons use 20 ms debounce and an 800 ms long-press threshold.
Button/slider navigation is active only in setup; in the dashboard these remain
normal RC controls. During setup their RC values are held at menu-entry values.
Slider navigation requires roughly +/-300/1024 deflection and neutral return
before the next step; holding a slider does not auto-repeat.
Both LEDs are steady on in dashboard mode, toggle every 250 ms in setup and
switch off during shutdown.
There is no i6X key matrix or physical trim-key bank; trims are adjusted in the UI.

=== FT6236 touch controller

[cols="2,3",options="header"]
|===
|Pins/peripheral |Use
|I2C1 PB8/PB9, AF1 |SCL/SDA, open drain, FT6236 7-bit address `0x38`.
|PA15 |Touch reset, active low.
|PC12 |Touch INT, active low; falling-edge EXTI12 latch, polled without NVIC/ISR.
|===

I2C1 uses the 48 MHz system clock and timing value `0x00B01A4B`.
It is independent of the EEPROM I2C speed option.
Initialization holds reset for 20 ms and waits 60 ms after release.
The controller's reset defaults are retained; CoreTX does not force registers
`0xA4`, `0x80` or `0x88`.

Transfers are cooperative, limited to 300 us/512 steps per service call.
A fresh interrupt starts a read without waiting for the normal polling interval.
While a contact remains active, reads continue every 8 ms even if INT returns high;
idle touch is not continuously polled.
A 300 ms stale-contact timeout releases the gesture, and failed transport is
retried after 250 ms.
Dashboard horizontal swipes change pages, vertical swipes scroll within a page;
MultiSwitch elements support their corresponding tap/hold actions.

=== Power and safe shutdown

*PB15* is the active-high power latch. *PB14* is the active-low common signal
of the two power buttons.
After boot the buttons must first be released.
Hold both buttons for 1.5 s to request shutdown.
CoreTX immediately disables RF, completes pending storage writes, switches the
LEDs off and only then releases the latch.
On a storage error it remains powered instead of cutting power during a failed save.
USB power may keep the device physically powered even after the latch is released.
For the first flash from factory firmware, temporarily bridge *R60* and use the
two-button ROM-entry procedure; no resistor removal is required in the documented
procedure. See link:BUILDING.adoc#first-flash-i6s[i6S first-flash steps and PCB reference].
After installing CoreTX with startup DFU support, hold both rear buttons
*SE/SF (PA9/PA10)* while switching on with the front power buttons.
This enters ROM DFU without a bridge before watchdog/EEPROM initialization;
PB15 remains high and GPIOB is not reset during handoff.
See link:BUILDING.adoc#dfu-update[power-on DFU and recovery].

=== Interrupts and unused resources

In normal firmware, with A7105 support enabled, the only application ISRs are
`TIM2_IRQHandler` and `EXTI2_3_IRQHandler`, both at priority 0
(`boards/common/rf_interrupts.cpp`). Shared RF state uses guarded handoff.
Touch EXTI12 is only a polled latch, not another ISR.
ADC/DMA, UART, touch I2C, EEPROM, buttons, LCD and buzzer run from the main loop.

DMA1 channel 1 is ADC, channel 2 CRSF TX, channel 3 CRSF RX;
channels 4 through 7 are unused. USART2, USB, CAN, DAC, comparators, SPI2 and
other timers are not used by the running application.
USB ROM DFU is a bootloader function, not a CoreTX USB implementation.
Unused peripherals do not imply their pins are free or exposed.

`CORETX_A7105=OFF` removes SPI/RF interrupt use, but TIM2 remains the timebase.
`CORETX_CRSF=OFF` removes UART/CRSF DMA use; safe module-off GPIO handling remains.
Do not infer that a build option makes connected hardware safe to rewire while powered.
